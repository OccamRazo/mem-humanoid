# 园区机器人巡检 Demo 数据采集方案（完善版）

> - 文档版本：V1.0
> - 适用范围：环保园 1 号楼周边固定巡检区域
> - 核心目标：采集可用于验证机器人 L1 工作记忆、L2 情景记忆和 L3 记忆巩固与图式化能力的多模态、连续、可追溯数据。
> - 说明：本文中的数量、频率和时长为 Demo 阶段建议基线。首次现场踏勘和试采后，应根据路线长度、传感器能力、班车时刻及人员配合情况冻结最终参数。

## 1. 项目背景与范围

### 1.1 记忆能力分级

- **L1 工作记忆维持与整合**：在有限时空窗口内维持高保真感官表征，并整合局部时间范围内的物体、关系、顺序和空间布局。
- **L2 情景记忆构建与检索**：将离散视觉事件组织为带有时间、空间和情境标签的长期记忆单元，建立事件间关联，形成可检索的经验轨迹。
- **L3 记忆巩固与图式化**：从多次具体经历中归纳稳定概念、规律、图式和世界知识，实现由事件记忆向抽象知识的压缩与泛化。
- **L4 记忆驱动的重构与预测**：利用已有记忆完成过去重构、未来预测、反事实模拟及行动路径推演。
- **L5 元记忆调控与终身优化**：监控和评估自身记忆状态，动态执行记忆强化、更新、重组与主动遗忘。

本次 Demo 仅采集和验证 L1—L3 所需数据，L4、L5 不纳入本阶段验收范围。

### 1.2 巡检机器人任务设定

宇树 G1 巡检机器人在园区固定范围内执行巡检。正常情况下沿预设路线行进；遇到预定义的异常或需近距离确认的目标时，可在安全规则允许的范围内短暂偏离路线，完成观察或记录后回到原路线继续巡检。

机器人仅依赖少量先验规则启动任务，在连续巡检中记录环境、物体、人物和事件，逐步形成：

1. 单次巡检内的短时连续认知；
2. 不同巡检批次之间的状态变化记忆；
3. 多日、多次观察后得到的区域功能、周期事件和异常处置知识。

### 1.3 Demo 边界

本阶段包括：

- 1 号楼周边固定路线的多模态数据采集；
- 真实自然场景与人工设置场景；
- 物体、事件、区域、变化和异常处置过程的结构化标注；
- 支持 L1—L3 能力验证的数据集划分与质量验收。

本阶段不包括：

- 未经审批的自主处置或危险操作；
- 对非参与人员进行身份识别；
- 基于记忆的长期自主策略优化；
- L4 预测、反事实推演和 L5 元记忆能力的正式验收。

## 2. 采集目标与验收问题

### 2.1 L1：单次巡检内的维持与整合

数据应能支持回答以下问题：

- 机器人能否在目标短暂离开视野后仍记住其存在、属性和位置？
- 对象分布超出单帧视野时，能否跨帧去重、计数并建立空间关系？
- 能否正确恢复单次巡检中事件的发生顺序、参与对象和前后状态？
- 中途绕障、转身或短暂遮挡后，能否继续关联同一对象或事件？

### 2.2 L2：跨巡检情景记忆的构建与检索

数据应能支持回答以下问题：

- 机器人能否检索某对象在某次巡检中的状态？
- 能否比较相邻或间隔多次巡检，识别位置、数量、朝向、外观、开合、倒伏、出现和消失等变化？
- 能否将“时间、地点、对象、事件、状态”组织为可追溯的情景记录？
- 面对相似对象或相似场景时，能否找到正确的历史记录，而不是混淆其他地点或批次？

### 2.3 L3：跨日规律与图式归纳

数据应能支持回答以下问题：

- 机器人能否从多次稳定观察中归纳未显式告知的区域功能？
- 能否归纳固定时间或地点反复发生的事件规律，并区分稳定规律与偶然现象？
- 能否从多次专业人员处置记录中总结异常判定依据、处置步骤和完成条件？
- 当部分观测缺失或存在少量扰动时，能否保持合理的规律总结？

## 3. 总体采集设计

### 3.1 数据单元

数据按以下层级组织：

| 层级 | 定义 | 示例 |
|---|---|---|
| 项目 Project | 本次完整 Demo 采集 | `EPARK_G1_DEMO_V1` |
| 日期 Day | 一个自然采集日 | `2026-08-18` |
| 巡检 Run | 从起点出发到回到终点的一次完整巡检 | `RUN_20260818_083000` |
| 路段 Segment | 两个固定地标或检查点之间的连续轨迹 | `CP03_TO_CP04` |
| 情景 Episode | 可独立描述的对象状态或事件片段 | “消防箱门打开” |
| 观测 Observation | 带统一时间戳的单帧或短时间窗记录 | RGB-D 帧、点云帧、语音片段 |

L1 主要使用单个 Run 内的连续观测，L2 主要使用多个 Run 的同地点记录，L3 主要使用跨多日的 Episode 集合。

### 3.2 建议采集规模

Demo 建议采用“10 个有效采集日 + 2 个机动补采日”，覆盖至少两个工作周。

| 项目 | 建议基线 | 最低有效要求 |
|---|---:|---:|
| 有效采集日 | 10 天 | 8 天 |
| 每日固定巡检 | 4 次 | 3 次 |
| 有效完整巡检 | 40 次 | 30 次 |
| 单次巡检时长 | 以试采实测为准，建议 20—40 分钟 | 完成全路线且无关键数据中断 |
| 路线检查点 | 8—12 个 | 8 个 |
| 重点对象实例 | 20—30 个 | 15 个 |
| 人工设置变化 | 每日 2—4 项 | 全周期不少于 20 项 |
| 人工设置异常 | 全周期 8—12 次 | 不少于 6 次 |
| 专业人员规范处置记录 | 每类异常不少于 2 次 | 关键异常类型至少 1 次 |
| 稳定规律样本 | 每个规律跨至少 5 天、出现至少 6 次 | 跨至少 4 天、出现至少 5 次 |

固定巡检时间建议覆盖：上班前后、午间、下午和下班前后。具体时间应结合班车、清扫和人员活动安排冻结，并尽量保持每日时间窗一致。

### 3.3 对照设计

为区分记忆能力与单帧识别能力，每类重点场景至少设置以下对照：

1. **稳定对照**：对象和环境保持不变，用于验证系统不会频繁误报变化。
2. **单因素变化**：每次只改变一个主要属性，如位置或数量，便于确定变化来源。
3. **相似干扰**：在相邻地点放置外观相似对象，测试跨地点检索和身份关联。
4. **遮挡与重现**：目标短暂被遮挡或离开视野后重新出现，测试工作记忆连续性。
5. **恢复场景**：异常处理后恢复正常状态，验证系统能否记录完整状态链。
6. **自然扰动**：保留少量光照、行人、车辆或天气变化，验证场景鲁棒性。

除专门测试多因素变化外，同一 Episode 不应同时引入多个未记录的变量。

### 3.4 建议的十日场景排期

下表用于保证各类变化、稳定负例和长期规律均有覆盖。现场可调整顺序，但调整后应同步更新场景真值表和覆盖矩阵。

| 有效日 | 当日重点 | 主要作用 |
|---|---|---|
| D1 | 全路线基线、对象建档、真实事件观测 | 建立初始状态和对象身份 |
| D2 | 小范围位置和朝向变化 | L2 单属性变化；持续观测 L3 区域规律 |
| D3 | 数量异常及首次专业处置 | L2 数量变化；积累处置图式 |
| D4 | 大部分场景保持稳定，仅保留自然扰动 | 稳定负例；防止变化误报 |
| D5 | 开合状态变化、遮挡后重现 | L1 连续关联；L2 状态变化 |
| D6 | 对象出现或消失、相似对象干扰 | L2 情景检索和实例区分 |
| D7 | 倾倒异常及专业处置 | L2 异常恢复；积累处置图式 |
| D8 | 恢复场景、跨日检索 | 验证完整状态链和长期记忆 |
| D9 | 对已采场景做新组合，但保持真值可分解 | 泛化测试；补齐覆盖缺口 |
| D10 | 隐藏验收场景和稳定对照 | 形成未参与调试的测试样本 |

班车、清扫等真实周期事件应在 D1—D10 的对应时间窗持续观察，而不是只在单独某一天采集。功能区域的核心物体组合在全周期内原则上保持稳定，只加入已登记的少量扰动。

## 4. 路线与空间设计

### 4.1 基础路线

- 路线方向：逆时针绕行园区 1 号楼。
- 起点和终点：选择网络、定位和人员值守条件稳定的位置，起终点原则上相同。
- 路线要求：可重复、可通行、可安全停靠，并能覆盖真实场景和设置场景。
- 每次正式巡检前后，在起终点保留不少于 10 秒静止数据，方便时间同步和轨迹检查。

### 4.2 检查点设计

现场踏勘后建立 8—12 个固定检查点，并为每个检查点记录：

- 唯一编号和名称；
- 地图坐标或局部坐标；
- 参考照片和显著地标；
- 标准观察位置、机器人朝向、推荐停留时长；
- 可观测目标及目标基线状态；
- 可能出现的遮挡、强反光、逆光、坡面、人车混行等风险；
- 是否允许偏航接近，以及允许接近的边界。

建议检查点类型如下：

| 检查点类型 | 目标 | 建议停留时间 |
|---|---|---:|
| 起终点 | 同步检查、任务开始和结束确认 | 10—20 秒 |
| 消防设施点 | 多对象计数、状态比较、异常验证 | 15—30 秒 |
| 公共设施点 | 长凳、烟灰缸、垃圾桶状态记录 | 10—20 秒 |
| 路口或转角 | 遮挡后关联、路线与空间关系 | 5—10 秒 |
| 班车观测点 | 到达、停靠、发车事件记录 | 覆盖完整事件 |
| 功能区域 | 区域用途与物体共现规律采集 | 10—20 秒 |

### 4.3 路线版本管理

标准路线冻结后生成 `route_version`。临时施工、封路或安全原因导致路线变化时，不直接覆盖旧路线，而是新建版本并记录变更原因。每个 Run 必须绑定一个路线版本。

## 5. 情景与对象设计

### 5.1 真实自然情景

#### 5.1.1 物体

重点记录长凳、烟灰缸、垃圾桶等真实公共设施。记录属性包括：

- 对象类别、实例编号和所在区域；
- 数量、位置、朝向和可见程度；
- 外观、完好程度、开合或满溢状态；
- 与相邻对象、道路、建筑入口的空间关系；
- 是否为常驻对象，以及首次和最近一次观测时间。

#### 5.1.2 事件

重点采集班车固定时间到达、停靠和发车。一个完整班车事件至少包含：

1. 班车尚未到达的前置状态；
2. 班车进入观测区域；
3. 停靠或人员上下车；
4. 班车发车并离开；
5. 事件结束后的环境状态。

在取得园区许可后，可增加固定时段清扫、垃圾清运等稳定事件。涉及人员时只标注角色和行为，不将非参与人员姓名作为采集目标。

### 5.2 人工设置情景

#### 5.2.1 对象范围

- 灭火器；
- 消防箱；
- 交通锥；
- 警示牌。

每个可控对象粘贴或登记不影响视觉任务的内部实例编号。标注文件使用实例编号，实际测试可同时保留“无编号可见”的图像条件。

#### 5.2.2 日常变化

日常变化建议每天设置 2—4 项，单项变化优先只修改一个属性：

- 小范围位置移动；
- 朝向变化；
- 对象次序交换；
- 正常开合状态变化；
- 临时出现或移除非关键对象。

变化应在巡检前由场景管理员登记，机器人执行人员不应提前获知具体变化，以减少操作提示造成的数据偏差。

#### 5.2.3 异常变化

异常建议每 2—3 天安排一次或多次，全周期覆盖下列类型：

| 异常类型 | 示例 | 前提与限制 |
|---|---|---|
| 数量异常 | 灭火器减少、交通锥缺失 | 使用演示道具或经管理方批准，不影响真实消防安全 |
| 位置异常 | 设备明显离开规定区域 | 不占用消防通道和车辆通道 |
| 姿态异常 | 交通锥、警示牌倾倒 | 不制造绊倒和碰撞风险 |
| 开合异常 | 消防箱门处于非基线状态 | 不破坏铅封，不操作真实受控设备 |
| 遮挡异常 | 目标被纸箱等安全物体部分遮挡 | 不妨碍真实设施使用 |
| 外观异常 | 演示设备出现可移除的污渍或标识 | 不对真实设备造成损伤 |

所有人工异常必须同时记录设置前、设置后、机器人发现时、专业人员处置中和恢复后的状态。禁止为了采集制造真实险情。

### 5.3 L1 专项情景

每类至少采集 3 个有效 Episode：

1. 多个同类对象跨视野分布，要求巡检后完成去重计数；
2. 同一对象经历“可见—遮挡—再出现”；
3. 经过转角后询问前一路段对象的属性或相对位置；
4. 连续发生 3—5 个有明确先后关系的动作或事件；
5. 临时偏离路线观察异常，再返回原路线继续任务；
6. 相似对象在不同检查点出现，要求保持地点和实例关联。

### 5.4 L2 专项情景

每种变化类型至少安排 3 个有效正例，并保留不少于正例数量的稳定负例：

- 位置变化；
- 数量增加或减少；
- 朝向变化；
- 开合或倒伏状态变化；
- 外观变化；
- 对象出现或消失；
- 异常处置后恢复。

变化间隔应同时包括“相邻两次巡检”和“跨日巡检”，以测试不同时间跨度的检索。

### 5.5 L3 专项情景

#### 区域功能归纳

选择 2—3 个不向系统显式提供用途名称的功能区域。每个区域在多个采集日中保持核心物体组合稳定，同时允许少量位置和数量扰动。示例：消防设施集中存放区、保洁工具临时放置区、班车停靠区。

#### 周期事件归纳

选择 2—3 类有稳定时间或地点规律的事件。每类事件应跨至少 5 个有效日出现 6 次以上，并设置 1—2 次合理扰动，如晚到、缺席或观测被遮挡，以验证系统不会把单次偏差直接覆盖长期规律。

#### 异常处置图式

为 2—3 类异常记录专业人员的规范处置过程。每次记录：触发条件、检查步骤、工具或角色、关键动作、完成条件和恢复状态。涉及真实消防或安全设备时，以园区制度和专业人员操作为准，机器人只观察和记录。

## 6. 采集数据与技术要求

### 6.1 数据模态

正式采集至少包含：

- RGB 或 RGB-D；
- 深度图（设备支持时）；
- IMU；
- LiDAR 点云；
- 机器人位姿、关节或里程计数据（设备可提供时）；
- Transcript，包括机器人提示、工作人员口述和任务问答；
- 统一 Timestamp；
- 任务、路线、场景和传感器元数据。

音频和 Transcript 仅在获得授权且确有任务需要时采集；如不保留原始音频，应记录转写来源和删除状态。

### 6.2 推荐采集参数

以下参数需在试采后结合设备能力冻结：

| 数据 | 建议参数 | 质量要求 |
|---|---|---|
| RGB | 不低于 1920×1080，15—30 fps | 不持续过曝、欠曝或严重运动模糊 |
| Depth | 与 RGB 对齐，15—30 fps | 记录量程、无效值定义和对齐方式 |
| LiDAR | 使用设备原生有效频率，建议不低于 10 Hz | 保留坐标系、时间戳和标定信息 |
| IMU | 建议不低于 100 Hz | 保留单位、轴方向和量程 |
| 位姿/里程计 | 建议不低于 10 Hz | 明确参考坐标系和置信度 |
| Transcript | 句级或事件级时间戳 | 可回溯到对应视频和 Episode |
| 系统时间 | 毫秒级统一时间戳 | 各模态可按时间对齐 |

若带宽或存储受限，优先保证连续性、同步性和原始时间戳，不应通过随机丢帧降低数据量。

### 6.3 时间同步与标定

- 所有传感器统一到同一时钟源；无法硬同步时，记录各设备时钟偏移并在采集后校正。
- 每日首个 Run 前执行时间同步检查；设备重启后重新检查。
- 正式采集前完成相机内参、相机—深度、相机—LiDAR及机器人本体外参标定。
- 传感器安装位置变化、碰撞或松动后必须重新标定，并更新 `calibration_version`。
- 每个 Run 保存同步状态和标定版本，不允许仅用文件创建时间代替传感器时间戳。

### 6.4 坐标系与空间基准

至少定义：`map`、`odom`、`base_link`、`camera`、`lidar`。对象位置标注优先同时保留地图坐标和机器人局部坐标；若地图定位短时失效，需标记失效区间和可用的替代位姿来源。

## 7. 现场采集流程

### 7.1 人员角色

| 角色 | 主要职责 |
|---|---|
| 采集负责人 | 排期、审批协调、版本冻结和最终验收 |
| 机器人操作员 | 启停、路线执行、紧急接管和运行日志 |
| 场景管理员 | 设置变化和异常、维护真值表，避免向操作员泄露测试答案 |
| 安全员 | 清场、风险监护和异常中止 |
| 数据管理员 | 数据落盘、备份、校验、脱敏和台账 |
| 标注/复核人员 | 标注、交叉复核和争议仲裁 |
| 专业处置人员 | 按园区规范处理特定异常并确认完成状态 |

人员不足时可以兼任，但“场景设置”和“机器人执行”建议由不同人员负责。

### 7.2 每日采集前

1. 确认天气、道路、施工、人车流和园区许可状态；
2. 检查机器人电量、急停、网络、存储空间和传感器固定状态；
3. 完成时钟同步、标定版本和数据写入测试；
4. 对路线进行安全巡查，确认没有无法绕行的临时障碍；
5. 拍摄各重点对象和检查点的当日基线真值；
6. 场景管理员按日程设置变化或异常并填写场景单；
7. 创建当日 Run 清单，分配唯一编号。

### 7.3 单次巡检

1. 在起点启动全部传感器并静止记录 10—20 秒；
2. 口述或写入 Run ID、路线版本、操作员和采集时间；
3. 按标准路线巡检，在检查点保持规定视角和停留时间；
4. 遇到异常时按规则执行“发现—复核—记录—上报”，未经授权不操作真实设施；
5. 发生绕障、偏离路线、人工接管、碰撞风险或数据中断时立即记入运行日志；
6. 回到终点后静止记录 10—20 秒，再统一停止传感器；
7. 操作员现场确认任务完整，场景管理员补录真值和恢复状态。

### 7.4 每次采集后

1. 检查所有必需模态文件是否存在且可读取；
2. 检查起止时间、时长、关键事件和各模态时间范围是否一致；
3. 生成文件清单和 SHA-256 校验值；
4. 将数据复制到主存储和独立备份各一份；
5. 完成 Run 级质检并标记“有效、部分有效、待补采或作废”；
6. 在下一次巡检前恢复场景，或准确记录场景继续保持变化的原因。

## 8. 标注方案

### 8.1 标注原则

- **先真值、后推断**：先记录现场可确认事实，再填写事件或规律标签。
- **实例一致**：同一物体跨帧、跨 Run 尽量使用同一 `object_id`。
- **时间可追溯**：所有事件必须有开始时间，能够确定时应记录结束时间。
- **不确定性显式化**：无法确认时使用 `unknown` 和置信度，不强行给出确定标签。
- **变更不覆盖历史**：对象状态变化新增记录，不覆盖上一批次的状态。
- **规则与数据分离**：采集真值表不直接写入供机器人推理的输入数据。

### 8.2 核心实体字段

#### Run 级元数据

| 字段 | 含义 |
|---|---|
| `run_id` | 巡检唯一编号 |
| `date`、`start_time`、`end_time` | 日期及起止时间 |
| `route_version` | 路线版本 |
| `calibration_version` | 标定版本 |
| `operator_id` | 操作员匿名编号 |
| `weather`、`illumination` | 天气和光照 |
| `sensor_status` | 各传感器状态 |
| `scenario_ids` | 本次关联的场景编号 |
| `route_deviation` | 是否偏离路线及原因 |
| `intervention` | 是否人工接管及原因 |
| `quality_status` | 有效、部分有效、待补采、作废 |

#### 对象状态

| 字段 | 含义 |
|---|---|
| `object_id`、`category` | 实例编号和类别 |
| `timestamp`、`run_id` | 观测时间和巡检编号 |
| `checkpoint_id` | 所在检查点或区域 |
| `position`、`orientation` | 位置和朝向 |
| `count` | 组级对象数量，实例标注时通常为 1 |
| `state` | 正常、打开、倾倒、缺失、遮挡等 |
| `visibility` | 完全可见、部分可见、不可见 |
| `bbox_or_mask` | 2D 框或分割掩码，按任务需要选用 |
| `point_or_3d_box` | 地图点或 3D 框，按能力选用 |
| `confidence` | 真值或标注置信度 |

#### 事件记录

| 字段 | 含义 |
|---|---|
| `event_id`、`event_type` | 事件编号和类型 |
| `start_ts`、`end_ts` | 开始和结束时间 |
| `location_id` | 发生地点 |
| `participants` | 对象或匿名角色列表 |
| `pre_state`、`post_state` | 事件前后状态 |
| `ordered_actions` | 有序动作序列 |
| `source_modalities` | 支撑该事件的模态 |
| `ground_truth_source` | 现场记录、视频复核或专业人员确认 |
| `confidence` | 标注置信度 |

#### 跨 Run 变化记录

至少记录 `object_id`、`previous_run_id`、`current_run_id`、`change_type`、`before_value`、`after_value`、`is_planned`、`scenario_id` 和 `verified_by`。

### 8.3 Transcript 规范

- 保留原始语言，不因语病改写语义；
- 记录发言者角色，如 `robot`、`operator`、`staff`、`bystander_unknown`；
- 每段转写包含开始和结束时间；
- 听不清内容标为 `[inaudible]`，不得凭上下文臆造；
- 姓名、电话、车牌等非任务必要信息应在发布版本中脱敏；
- 机器人问答数据需区分“在线回答”和“事后评测问题”。

### 8.4 L1—L3 派生标注

- **L1**：对象首次出现、最后出现、遮挡区间、重现时间、跨帧实例关联、事件顺序和单 Run 计数真值。
- **L2**：同对象跨 Run 链接、状态变化类型、变化发生区间、最近一次相同状态和检索目标 Run。
- **L3**：区域—物体共现统计、周期事件出现记录、例外记录、规律适用时间窗、异常处置步骤和支持样本列表。

L3 规律标签必须链接到多个原始 Episode，不允许只依据一次观察生成。

## 10. 数据质量控制与验收

### 10.1 Run 级有效性

满足以下条件可判定为“有效完整巡检”：

- 完成标准路线，或偏离部分有明确日志且不影响主要场景覆盖；
- 所有在试采后冻结为“必需”的模态均存在且连续可用；仅标为“可选”的模态缺失时，不影响完整巡检判定；
- 关键检查点覆盖率不低于 90%，消防和异常检查点必须覆盖；
- 必需模态无单段超过 5 秒的无说明中断；
- 关键 Episode 的前置、发生和结束状态可追溯；
- 元数据、真值表和校验文件齐全。

不满足完整巡检要求但仍可用于局部任务的数据标为“部分有效”，不得计入完整巡检数量。

### 10.2 数据级质量指标

| 指标 | 建议验收线 |
|---|---:|
| 必需文件完整率 | 100% |
| 关键检查点覆盖率 | ≥ 90% |
| 关键 Episode 覆盖率 | 100% |
| 多模态时间范围重叠率 | ≥ 98% |
| 关键片段同步误差 | 试采后冻结；建议视觉—点云 ≤ 100 ms |
| 对象实例标注一致率 | ≥ 95% |
| 事件边界复核一致率 | 容差 ±1 秒内 ≥ 90% |
| 抽检标注准确率 | ≥ 95% |
| Run 元数据完整率 | 100% |
| 文件校验通过率 | 100% |

### 10.3 标注质检

- 100% 自动检查字段、枚举值、时间范围、外键和文件路径；
- 不少于 20% 的 Run 由第二名标注员复核；
- 所有异常 Episode、规律标签及低置信度标注必须人工复核；
- 对象跨 Run 关联冲突和事件顺序冲突进入仲裁表；
- 修订后递增标注版本，保留修改人、时间和原因。

### 10.4 防止数据泄漏

训练、验证和测试划分不能仅随机拆分相邻视频帧。建议按日期和场景实例分组：

- 训练集：约 60%，用于系统开发；
- 验证集：约 20%，用于参数和提示调整；
- 测试集：约 20%，在验收前保持隐藏。

同一人工异常的一段连续过程及其相邻帧必须位于同一集合。L3 测试还应保留未参与规则总结的后续日期，用于验证规律泛化。

## 11. 能力评测建议

数据采集验收以数据质量为主，系统能力可使用以下指标进行 Demo 展示：

### 11.1 L1 指标

- 单 Run 对象去重计数准确率；
- 遮挡后实例重关联准确率；
- 对象属性和相对位置问答准确率；
- 事件顺序准确率或 Kendall 等级相关；
- 偏航后任务上下文恢复成功率。

### 11.2 L2 指标

- 指定时间、地点和对象的历史检索 Recall@K；
- 状态变化分类准确率、Precision、Recall 和 F1；
- “未变化”负例的误报率；
- 变化前后状态描述准确率；
- 跨 Run 同一对象关联准确率。

### 11.3 L3 指标

- 区域功能归纳准确率及证据覆盖率；
- 周期事件的时间窗、地点和频率总结误差；
- 对偶然异常的过度概括率；
- 异常处置流程的关键步骤覆盖率和顺序准确率；
- 规律结论到原始 Episode 的可追溯率。

具体系统通过线应在模型基线跑通后冻结，避免在没有基线结果时给出失真的固定阈值。

## 12. 安全、隐私与合规

- 采集前获得园区、设施管理方和必要参与人员授权，并设置现场提示；
- 不采集与任务无关的敏感区域、屏幕、证件、门禁凭据和个人对话；
- 对非参与人员的人脸、车牌和可识别语音按发布范围进行遮挡、模糊或删除；
- 真实消防设施不得擅自移动、拆封、断电或长时间保持异常状态；
- 人车混行、道路阻塞、失稳风险、网络失联或急停异常时立即中止任务；
- 明确数据保留周期、访问权限、发布范围和删除流程；
- 原始数据最小权限访问，外发数据必须经过脱敏和审批。

## 13. 实施计划

### 阶段 A：踏勘与冻结（1—2 天）

- 确认路线、检查点、真实事件时间和安全边界；
- 建立对象台账、场景库和地图；
- 冻结传感器参数、命名规范和表单。

### 阶段 B：试采与复盘（1 天）

- 完成不少于 2 次全路线试采；
- 验证同步、标定、存储、视角和停留时间；
- 跑通数据导出、标注、质检和备份闭环；
- 根据试采结果冻结最终基线参数。

### 阶段 C：正式采集（10 个有效日）

- 按固定时间窗执行巡检；
- 真实场景连续观测，设置场景按日程轮换；
- 每日完成数据质检和问题闭环，不将问题积压到采集结束。

### 阶段 D：补采与标注（2—4 天）

- 按覆盖矩阵补齐缺失场景；
- 完成对象、事件、变化和规律标注；
- 完成交叉复核和脱敏。

### 阶段 E：数据验收与发布（1—2 天）

- 输出数据清单、质量报告、场景覆盖报告和已知问题；
- 冻结数据集版本；
- 生成 L1—L3 评测任务和隐藏测试集。

## 14. 交付物

1. 原始多模态数据及校验清单；
2. 标定文件、地图和路线版本；
3. Run 元数据、场景真值表和运行日志；
4. 对象、事件、跨 Run 变化和 L3 规律标注；
5. 数据字典与标注手册；
6. 数据质量、覆盖率和脱敏报告；
7. 训练、验证和隐藏测试划分；
8. L1—L3 Demo 评测题集及基线结果（系统可运行后补充）。

## 15. 正式采集前必须明确的问题

以下问题应在阶段 A 或阶段 B 结束前形成书面结论：

1. G1 实际搭载的相机、深度、LiDAR、IMU、音频和定位设备型号及可用参数是什么？
2. 单次路线的实测长度、时长、定位盲区和网络盲区是什么？
3. 班车实际时刻、停靠位置和可稳定观测时间是什么？
4. 哪些区域允许机器人停留、转身、偏航接近或进行口头播报？
5. 哪些消防设施可用于演示，是否需要使用独立演示道具？
6. 异常判定规则、上报对象和专业处置 SOP 由谁提供并确认？
7. 是否允许采集音频、人员图像和车牌；脱敏后数据可在什么范围使用？
8. 多模态数据的目标格式、坐标系、时间同步精度和最大存储预算是多少？
9. L1—L3 的评测接口、问题形式和系统基线何时冻结？
10. 雨天、施工、临时封路、设备故障和真实突发事件的补采规则是什么？
