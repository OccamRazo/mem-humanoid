# 项目约定

本文件承接 [原版项目指南](../AGENTS_org.md) 中的领域约定，并按当前各目录的 `AGENTS.md` 组织材料。仓库通用协作规则以 [根目录指南](../AGENTS.md) 为准；原版保留作历史参考，不作为并行生效的管理入口。

## 研究目标与边界

面向长期运行的巡检机器人，研究可靠、长期、可演化的记忆系统：持续记录和利用经验，改善环境理解、变化与异常检测、规划和响应，最终支持安全、可验证、可回滚的自进化。

| 层级 | 研究内容 |
| --- | --- |
| L1 工作记忆 | 有限时空窗口内维持、关联和整合对象、关系、顺序与空间布局 |
| L2 情景记忆 | 组织带时间、空间和上下文的经历，支持跨巡检检索与变化比较 |
| L3 语义与图式记忆 | 从多次经历归纳概念、常态、周期和流程，保留证据、适用范围与版本 |
| L4 记忆驱动的重构与预测 | 支持历史重构、预测、反事实推演和行动规划 |
| L5 元记忆 | 评估记忆质量，调节写入、检索、更新、压缩和遗忘 |

园区 Demo 优先验证 L1—L3；L4、L5 与受控自进化是后续方向。具体阶段和验收条件见 [路线图](plan/roadmap.md)。不得未经明确要求固定模型、数据集、技术路线、机器人平台或投稿目标。`src/HoloAgent` 是可替换的外部平台基线，不代表已选定本项目记忆系统实现。

## 文件归属

| 位置 | 内容与入口 |
| --- | --- |
| [research/](../research/README.md) | 按文内调研截止或版本日期组织文献、证据、研究提案与假设；规则见 [research/AGENTS.md](../research/AGENTS.md) |
| [docs/](README.md) | 根部保存约定、协作说明与状态；执行计划集中在 [plan/](plan/README.md)，按用途或主题组织 |

| [src/](../src/README.md) | 持续维护的共用模型、记忆、数据处理、评估与平台适配代码；一次性验证代码先放所属实验的 `code/` |
| [data/](../data/README.md) | 数据来源、获取步骤、版本、划分、模式、小型元数据和校验信息；不保存大型原始数据 |
| [notes/sessions/](../notes/sessions/) | 按平台完整会话 ID 保存简洁上下文；通过 session-notes 技能定位 |
| [writing/](../writing/README.md) | `drafts/` 保存论文草稿；`figures/` 保存可入库图表与生成说明，大型生成产物留在本机；演示文稿按实际需要建目录 |

只创建实际需要的目录。研究材料不再按 `ideas/`、`literature/`、`hypotheses/` 分设顶层目录；类型通过文件名、文内说明和时间索引区分。同一调研的正文、附录与源数据放在一起；同日存在独立调研时才加主题子目录，已有 `survey_1/`、`survey_2/` 分组予以保留。日期未知时使用 `undated/`，不能用修改时间、Git 时间或文内示例日期代替版本日期。

研究提案中的实施设想可保留在原文；需要独立维护的执行步骤放入 `docs/plan/` 并引用提案，避免复制完整设计。实验立项后，其协议、配置、运行记录和结论由实验目录承担。

## 研究材料的最小内容

以下内容合并自旧 `research/ideas/README.md`、`literature/README.md` 和 `hypotheses/README.md`，避免维护重复规则。

### 想法与提案

每个独立想法说明背景、问题、为何记忆是必要变量、核心机制、替代解释、预期收益与成本、风险与失败模式、支持及反对证据、如何形成可证伪假设。状态明确写为探索中、进入假设、暂停或否定；提案不能当作已验证结论。

### 文献与证据

记录题目、作者、年份、稳定链接或 DOI/arXiv 标识，以及研究问题、场景、数据、方法、对照、指标、相关结果、适用边界、局限与偏差。链接对应提案、假设或实验。横向证据表中的关键数字必须可追溯到原文位置或公开结果，不能直接混排不同协议的性能。

### 可检验假设

实验开始前将选定假设写成独立、可定位版本的文件，并冻结首版。可使用 `H-<编号>` 作为文内标识，文件存入其声明版本日期下的研究目录。至少包含：

- 可证伪陈述、背景与证据；
- 自变量、因变量、控制变量、适用场景与边界；
- 基线、替代解释、数据、指标、支持条件与否定条件；
- 风险和安全约束、对应实验、状态与结论。

必须说明记忆如何影响任务结果，设置对照以区分长期记忆收益、当前观测收益、数据泄漏与场景捷径。未选定执行的候选假设可留在提案中，不为补目录而虚构立项。

## 证据与复现

- 区分文献事实、作者观点、项目推断、待验证想法与实验结论。可验证事实引用论文、链接或其他原始来源。
- 完整保存从调研、问题和假设到实验、分析及写作的过程。保留原始调查、失败运行、异常和负面结果；重大修订另存并链接前版。
- 实验固定并记录可控随机种子、代码提交、环境、配置、数据划分、模型与关键依赖版本、运行命令和统计方法。按独立运行保留记录，具体格式见 [工作记录](work-records.md)。
- 结论不得超出样本、时间、场景与评估协议支持的范围；报告排除样本、失败、限制和未解决问题。历史检查不能表述为本机新验证。
- 共用逻辑在明确选定持续维护后集中到 `src/`；实验专用代码和依赖留在实验 `code/`，避免复制分叉或提前引入全项目依赖。
- 数据、权重、完整日志、缓存和大型产物保留在产生它们的设备；Git 只保存小型证据、摘要、获取与复现说明。历史绝对路径不是当前设备可用性的证明。
- 图表必须能定位数据版本、生成方法和运行记录；不得手改数值美化结果。图表论断与原始数据及实验结论保持一致。
- 研究过程默认用中文记录，投稿内容可使用英文；文件名、实验 ID 和代码标识保持简洁、一致。
