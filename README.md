# Mem Humanoid

面向长期运行巡检机器人的记忆系统研究项目。

项目关注的不是为机器人简单增加一层对话历史，而是建立一套能服务真实巡检闭环的记忆基础设施：它应可靠、长期、可演化，能够从持续观测和任务反馈中形成经验，并最终支持受控、可验证、可回滚的机器人自进化。

## 目标概览

- 可靠地记录感知、事件、状态、行为和反馈，并保留时间、空间、来源、置信度与版本。
- 在单次巡检、跨巡检和跨日尺度上完成记忆构建、检索、巩固、更新与受控遗忘。
- 利用记忆进行变化检测、异常识别、上下文恢复、预测、规划和处置辅助。
- 在新经验持续进入时控制错误累积、知识冲突、灾难性遗忘和资源增长。
- 通过评估门禁、权限控制和回滚机制，让知识、记忆策略或技能安全地演化。

项目边界和研究要求见 [项目约定](docs/project-guide.md)，阶段路线见 [路线图](docs/plan/roadmap.md)，通用协作规则见 [AGENTS.md](AGENTS.md)。

## 当前状态

项目处于研究设计阶段，已有巡检系统调研、L3 记忆巩固提案和配套文献证据，尚无已立项实验目录及运行结果。三份园区巡检 Demo 采集文档作为历史探索材料保留，其中两份详细版本仅有排版差异。当前任务和下一步见 [项目状态](docs/STATUS.md)，研究材料见 [时间索引](research/README.md)，计划及版本关系见 [计划索引](docs/plan/README.md)。

`src/HoloAgent` 是可替换的外部机器人平台基线，不等同于本项目的记忆系统方案。

当前不预设具体模型、向量数据库、知识表示、数据集、机器人平台或投稿目标。后续选择需要由研究问题、可复现实验和任务级证据驱动。

## 能力分层

| 层级 | 关注能力 | 典型巡检问题 |
| --- | --- | --- |
| L1 工作记忆 | 有限时空窗口内的维持、关联与整合 | 目标离开视野后能否继续追踪、计数和恢复顺序？ |
| L2 情景记忆 | 带时间、空间和上下文的经历组织与检索 | 当前状态与上次巡检相比发生了什么变化？ |
| L3 语义/图式记忆 | 从多次经历中归纳规律、概念和流程 | 哪些区域具有稳定功能，哪些事件具有周期性？ |
| L4 生成式记忆 | 重构、预测、反事实与行动推演 | 异常可能如何发展，下一步应检查哪里？ |
| L5 元记忆 | 评估和调节记忆自身 | 什么值得记、何时更新、压缩、遗忘或请求复核？ |

园区 Demo 当前优先验证 L1—L3；L4、L5 和受控自进化属于后续阶段。

## 仓库导航

- [research/](research/README.md)：按文内日期组织调研、提案、文献证据和可检验假设。
- [experiments/](experiments/README.md)：按实验 ID 保存配置、运行记录、结果和结论。
- `data/`：数据说明、采集来源、划分与小型元数据，不存放大型原始数据。
- `src/`：可复用实现及外部机器人平台基线。
- [docs/](docs/README.md)：根部保存约定与当前状态，`plan/` 保存执行计划。
- `notes/sessions/`：按会话 ID 保存的简洁协作记录。
- `writing/`：论文草稿和可追溯图表。

各目录以 `README.md` 导航；`research/`、`docs/` 和 `experiments/` 的目录规则见各自的 `AGENTS.md`。

## 开始研究

1. 在 `research/YYYY-MM-DD/` 记录直接相关的文献证据，日期取文内调研截止或版本日期；日期未知时使用 `undated/`。
2. 把选定想法改写为可证伪假设，明确对照组、指标和失败条件；更新研究时间索引，必要的执行计划放入 `docs/plan/`。
3. 实际立项时在 `experiments/EXP-YYYYMMDD-short-name/` 建立独立实验，按 [工作记录规范](docs/work-records.md) 记录版本、环境、种子、方法和结果。
4. 实验专用代码和依赖先放在该实验的 `code/`；明确选择持续维护的共用实现放入 `src/`。大型数据、权重和日志留在本机，只提交小型记录和复现输入。
5. 只有在跨时间、任务级评估支持时，才提升关于可靠性、长期性、演化或自进化的结论强度。

如需获取外部平台基线，初始化根仓库后运行：

```bash
git submodule update --init --recursive
```

使用或分发 HoloAgent 前应阅读其自身的 `LICENSE` 与第三方许可说明；其中部分依赖存在额外的商业使用限制。
