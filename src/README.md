# 源码与平台基线

本目录用于持续维护的模型、记忆、数据处理和评估代码。一次性验证代码、测试和专用依赖先放在所属实验的 `code/`；明确选定继续维护的共用逻辑再提升到这里，避免实验目录中的副本逐渐分叉。实验归档与复现要求见 [实验目录规则](../experiments/AGENTS.md)。

## HoloAgent

`HoloAgent/` 当前作为外部机器人平台基线，以 Git 子模块方式固定到特定上游提交。它可用于理解或复用机器人感知、导航、控制和数据录制能力，但不代表本项目已经选定其作为最终平台，也不代表已有代码满足本项目的记忆目标。

更新该子模块必须单独评审上游差异、许可证、接口兼容性和复现实验影响。HoloAgent 自身许可文件提示部分第三方依赖存在商业使用限制，在集成或分发前必须完成许可核查。

## 后续代码组织原则

只有在实际需要时才创建模块。优先围绕稳定职责拆分，例如记忆接口、数据契约、评估与平台适配；不要在尚未形成研究假设前预建复杂框架。平台相关代码与记忆核心之间应通过明确接口隔离，使替换机器人、传感器、模型或存储后端不会重写整个实验流程。
